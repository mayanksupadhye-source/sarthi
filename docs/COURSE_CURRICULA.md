### Work-estimation rule

For coding-heavy lessons, the owner estimates total effort at about 1.5×–1.75× video duration because code must be written alongside the lecture. Use 1.6× as a configurable starting multiplier. Store video duration separately from practice/review effort. For a lecture of duration `V`, a starting estimate is `totalEffort = V × 1.6`, not simply `V`.

### Fixed two-hour practice format in the source document

| Duration | Activity |
|---:|---|
| 30 min | Learn the week's one oratory skill |
| 30 min | Write a speech: Hook → Introduction → 3 Main Points → Story/Example → Conclusion |
| 15 min | Record first attempt, no stopping/restarting |
| 15 min | Review and score structure, confidence, gestures, voice, persuasion |
| 20 min | Drill only the one biggest mistake |
| 10 min | Record final attempt and compare |

The source asks for two recordings per week, 13 feedback loops, and progression without restarting the whole 13-week cycle if a week is missed. Resume from the next week. Track the week's skill, speech draft, first/final recording links if provided, five scores, one improvement, and reflection.

## Importing this reference into Shloki

The application should create editable course/section/lesson records from this reference. Avoid hard-coding completion dates. Let the owner choose a target completion date and available weekly capacity before auto-generating tasks. Do not assume all 331 web lessons and 136 DSA lectures can fit into a particular month without calculating total estimated effort and checking actual available hours.
